## Threat model and mandatory boundaries

- Untrusted PRs/dependencies must never obtain cloud credentials. CI is credential-free and isolated from operational execution. Privileged workflows require trusted reviewed current main, exact OIDC trust, independently verified protected environments and the explicit true AWS flag. A separate main-only protected preflight checks GitHub configuration with a read-only token while the flag remains false; it must never issue an OIDC request or run AWS/Terraform/backend operations. Shared validation cannot become a generic operational bypass. Do not expose API bodies or sensitive identifiers.
- The approved single-maintainer model requires the PR protection object and strict successful `verify` before merge, with zero required human PR approvals, `require_last_push_approval=false` and `require_code_owner_reviews=false`. At count zero, accept boolean `dismiss_stale_reviews=false` or `true`; reject missing/malformed values. Retain administrator enforcement and no PR bypass actors. Nonempty valid deployment reviewers remain required with the owner configured as a required reviewer; the initiating owner may explicitly approve (`prevent_self_review=false`) but administrators cannot bypass (`can_admins_bypass=false`). Restrict deployment to exactly main, no tags. Independent AI review is code/test analysis, not human separation of duties: one owner can author and approve, leaving owner error/account compromise as an explicit residual risk. Human exact private plan review and protected approval before apply remain mandatory; CI or a plan digest alone cannot replace them.
- IAM escalation/state theft are constrained by distinct runtime roles, exact resource/key/lock scopes and no runtime IAM/bootstrap administration. First resource creation/recreation needs an authorized local operator's exact privately reviewed saved plan, followed by exact distribution/OAC/header-policy ID binding; wildcard CloudFront tagging/creation is not an acceptable substitute.
- Plan leakage/tampering and approval bypass require private substantive plan review, authenticated ciphertext-only handoff if needed, digest/source/operation/freshness checks and protected approval after review. A digest alone is not substantive review.
- Public origin access/insecure transport are blocked by S3 public blocks, SSE-S3, TLS policies and distribution-scoped OAC; CloudFront uses HTTPS redirects and restrictive headers. Default-certificate legacy viewer TLS behavior remains a documented exception, not a TLS1.2 minimum claim.
- Concurrent operations/destruction require native state locks, repository-wide non-cancelling production concurrency, read-only drift and typed protected site-only destroy. Local operators must coordinate beyond repository concurrency. Bootstrap/state removal needs separate authorization.
- Privacy and evidence loss are addressed by approved content only, secret scans and sanitization, individual exception review and independent inventory approval before any cleanup deletion or archival move. No original PDF/private contacts/credentials/state/plan contents may enter evidence.
