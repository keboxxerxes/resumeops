# Security review and control exceptions

## Scope and release boundary

Linux CLI and GitHub-hosted Ubuntu CI are the supported verification environments. Native Windows Terraform support and troubleshooting are out of scope; the earlier certificate-substitution observation is a historical decision, not an active failure gate or a reason to weaken TLS. The cleanup revision must pass its own independent checks: the successful CI for an earlier revision is evidence of that revision only. See [verification](VERIFICATION.md) and [decisions](decisions/001-linux-first-terraform.md).

Only credential-free CI may execute under `.github/workflows`. Future content, drift and infrastructure/destroy workflows remain inert in `workflow-templates/`. Moving or enabling them requires separate explicit authorization and review. Public exposure, AWS credentials/account calls, IAM changes, resource creation, plan/apply/destroy, deployment, merge and history rewriting are not authorized by cleanup or a readiness verdict. No private contact, PDF, credential, state, plan, raw diagnostic/job log, certificate/key or local cache belongs in committed source.

## Threats and inspected source controls

| Boundary / threat | Control and limit |
|---|---|
| Malicious code or dependency obtains cloud authority | Sole active CI has contents-read GitHub permission, no OIDC/cloud authentication, custom secrets, deployment environment or operational path. Pinned actions/tools/provider locks and real negative scanners remain mandatory. Ordinary short-lived read-only GitHub job authentication is not an AWS credential. |
| State disclosure or role escalation | Separate bootstrap and site state/keys. Plan can read only site state and modify its exact lockfile; apply can write but not delete that state; content can write only four asset keys and invalidate the exact distribution. No runtime IAM administration, role chaining or bootstrap-state access. These are reviewed source policies, not live authorization proofs. |
| Broad CloudFront mutation | Initial creation/recreation is a separately authorized operator action on a privately reviewed saved plan. Bootstrap then binds exact distribution/OAC/header-policy IDs before runtime changes. No wildcard runtime creation or retagging privilege; unconfigured IDs fail closed. |
| Public origin or insecure transport | Explicit private S3 blocks, encryption/versioning, ownership enforcement, HTTPS deny and distribution-scoped OAC. CloudFront redirects HTTPS and applies restrictive response headers. The default certificate's legacy TLS residual is separately disclosed below. |
| Workflow/approval bypass | Future OIDC trust requires exact repository/environment subjects and STS audience. API-verified main-only environments, independent approval, no self/admin/PR bypass, current reviewed source and strict required checks precede credentials. Unavailable protections/API fail closed; actual account-plan availability is unverified. |
| Plan leakage/substitution or privileged rollback | Future apply uses a fresh binary, authenticated ciphertext only, same-run artifact, digest/source/operation checks and 24-hour age limit. Review the substantive plan privately before approval. Rollback extracts regular allowlisted prior assets using current trusted tooling; historical scripts do not execute. None is an active cloud path during verification. |
| Concurrency, deletion or loss | Native S3 lockfile and shared non-cancelling operational concurrency; typed protected site-only destroy; separate versioned state with `prevent_destroy`; bounded histories and deliberate recovery/teardown order. Locks are not auditing, and versioning is not regional disaster recovery. |
| Personal-data/cost exposure or false security claims | Approved resume baseline only; no private contact/PDF/trackers/external fonts. Private inputs and deployment metadata remain separated from source. Secret scanning, immutable revision/run evidence, all individual failures and live NOT RUN gates are retained. Budget alerts notify; they do not cap spending. |

The verification runner must retain recursive format checks, both backend-disabled readonly initializations and real validations, both lints, Checkov, actionlint for active/inert workflows, secret and provenance checks, unsafe IaC/workflow fixtures, IAM/API/crypto/drift negative tests, browser/accessibility/local smoke tests and lock immutability. A dependency/link check supplements these controls; it cannot replace them. Provider versions, all original archive/content hashes and narrowly justified exceptions remain intact. Source, actual CI and deployed behavior are separate evidence categories.
