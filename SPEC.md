## Goal and boundaries
One end-to-end SDD implementation of a standalone public portfolio: static professional resume, AWS Terraform and GitHub Actions. No milestones, backend, database, containers, Kubernetes, AI runtime, or dependency on another project. Use requirements/RESUME_CONTENT.md as the approved content baseline; do not invent achievements or publish private contact details. Human approval is required for publishing personal content, creating billable resources, changing account IAM, merging, and destruction.

## Functional acceptance criteria
- Responsive semantic HTML/CSS/vanilla JS; accessible keyboard navigation, reduced-motion support, readable contrast, career timeline, skills, education, and architecture section. No trackers or external fonts required. Link to public repository only once known. Display deployment SHA/date generated by CI; never claim a deployment or security status without evidence. No original PDF in public repo.
- Terraform root plus reusable website module; separate bootstrap state/IAM from site resources. Private S3 origin with all public access blocked, encryption, CloudFront OAC and HTTPS redirect, scoped bucket policy, default root object. Default CloudFront hostname; no paid custom domain. Separate state bucket with encryption, versioning, public access block, native S3 lockfile and restricted permissions. Commit provider lockfile; pin supported Terraform/provider versions. Explicit environment configuration and separate state keys; only production persistent, optional temporary dev. Document state bootstrap/migration and teardown order; protect state from site destroy.
- GitHub OIDC roles restricted to exact repository and trusted branch/environment subjects and sts audience; separate plan, infrastructure apply, and content deployment permissions; no long-lived keys. Avoid broad IAM escalation, scope permissions and document unavoidable exceptions. Bootstrap via authorized local operator only. Verify GitHub plan/environment protection availability; fail closed if required protections are unavailable.
- GitHub Actions: PR CI (fmt, init -backend=false, validate, TFLint, Checkov, secret scanning, website tests); credentialed plan only for explicitly trusted reviewed code, never untrusted forks or pull_request_target checkout. Apply trusted main revision with protected environment and human approval; generate fresh plan and apply exact reviewed plan, keep sensitive plan/state out of public artifacts/logs. Separate website deploy on trusted main or manual dispatch, upload only approved site assets, invalidate necessary paths, run HTTPS smoke checks. Serialize operations sharing state or site, including drift/destroy. Use minimal workflow/job permissions, SHA-pinned third-party actions, safe expression handling, timeouts and bounded artifact retention. No public secrets, account IDs or sensitive state outputs.
- Scheduled read-only drift detection: distinguish exit 0/1/2, report drift without applying. Rollback via approved previous content revision/redeployment; verify site and metadata. Manual destroy: explicit typed confirmation, protected approval, scope site only, retain bootstrap/state unless separately authorized. Document recovery and first deployment sequencing.
- Cost: target < $1 USD/month at low traffic, budget $5 USD/month; Terraform-managed actual spend alerts at $1/$3/$5 to private operator-provided address; no hard-cap claim. Verify current pricing/allowances before live deployment. No EC2, NAT, ALB, paid KMS keys, Route53 or unnecessary resources; bounded S3 noncurrent versions, avoid excessive invalidations/logging. Never embed alert email in committed files. Budget may cover account-wide spend; explain scope.
