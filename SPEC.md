# ResumeOps — specification

## Goal and boundaries
One end-to-end SDD implementation of a standalone public portfolio: static professional resume, AWS Terraform and GitHub Actions. No milestones, backend, database, containers, Kubernetes, AI runtime, or dependency on another project. Use requirements/RESUME_CONTENT.md as the approved content baseline; do not invent achievements or publish private contact details. Human approval is required for publishing personal content, creating billable resources, changing account IAM, merging, and destruction.

## Functional acceptance criteria
- Responsive semantic HTML/CSS/vanilla JS; accessible keyboard navigation, reduced-motion support, readable contrast, career timeline, skills, education, and architecture section. No trackers or external fonts required. Link to public repository only once known. Display deployment SHA/date generated by CI; never claim a deployment or security status without evidence. No original PDF in public repo.
- Terraform root plus reusable website module; separate bootstrap state/IAM from site resources. Private S3 origin with all public access blocked, encryption, CloudFront OAC and HTTPS redirect, scoped bucket policy, default root object. Default CloudFront hostname; no paid custom domain. Separate state bucket with encryption, versioning, public access block, native S3 lockfile and restricted permissions. Commit provider lockfile; pin supported Terraform/provider versions. Explicit environment configuration and separate state keys; only production persistent, optional temporary dev. Document state bootstrap/migration and teardown order; protect state from site destroy.
- GitHub OIDC roles restricted to exact repository and trusted branch/environment subjects and sts audience; separate plan, infrastructure apply, and content deployment permissions; no long-lived keys. Avoid broad IAM escalation, scope permissions and document unavoidable exceptions. Bootstrap via authorized local operator only. Verify GitHub plan/environment protection availability; fail closed if required protections are unavailable.
- GitHub Actions: PR CI (fmt, init -backend=false, validate, TFLint, Checkov, secret scanning, website tests); credentialed plan only for explicitly trusted reviewed code, never untrusted forks or pull_request_target checkout. Apply trusted main revision with protected environment and human approval; generate fresh plan and apply exact reviewed plan, keep sensitive plan/state out of public artifacts/logs. Separate website deploy on trusted main or manual dispatch, upload only approved site assets, invalidate necessary paths, run HTTPS smoke checks. Serialize operations sharing state or site, including drift/destroy. Use minimal workflow/job permissions, SHA-pinned third-party actions, safe expression handling, timeouts and bounded artifact retention. No public secrets, account IDs or sensitive state outputs.
- Scheduled read-only drift detection: distinguish exit 0/1/2, report drift without applying. Rollback via approved previous content revision/redeployment; verify site and metadata. Manual destroy: explicit typed confirmation, protected approval, scope site only, retain bootstrap/state unless separately authorized. Document recovery and first deployment sequencing.
- Cost: target < $1 USD/month at low traffic, budget $5 USD/month; Terraform-managed actual spend alerts at $1/$3/$5 to private operator-provided address; no hard-cap claim. Verify current pricing/allowances before live deployment. No EC2, NAT, ALB, paid KMS keys, Route53 or unnecessary resources; bounded S3 noncurrent versions, avoid excessive invalidations/logging. Never embed alert email in committed files. Budget may cover account-wide spend; explain scope.

## Verification and release gates
Local checks: Terraform fmt/validate for each root, lint, security scan, workflow syntax/actionlint, secret scan, browser tests at mobile/desktop, accessibility checks, smoke tests with local server. Include negative tests for insecure IaC and unsafe workflows; document any narrowly justified scanner exceptions, never suppress blindly. Verify dependency versions and SHA pins from authoritative sources. Test against actual AWS only after authorization, including OIDC, state lock, HTTPS, origin privacy, deployment, drift, rollback and teardown (temporary environment only if authorized). Capture sanitized commands, exit codes and CI links. Distinguish PASS/FAIL/NOT RUN; no fabricated evidence. All confirmed security findings must be closed or release is NO-GO. Any missing mandatory live verification prevents a live-release GO; local readiness may be reported separately.

## Deliverables
Website, Terraform, workflows, tests, README with setup/architecture/cost/rollback/teardown, docs/IMPLEMENTATION_REPORT.md, TEST_RESULTS.md, SECURITY_REVIEW.md, FINAL_ASSESSMENT.md, and sanitized SDD plan/evidence. Human retains final release authority.

## User-approved continuation: private credential-free verification

Continue the same end-to-end SDD cycle; this is not a milestone or restart. The user explicitly authorizes creating the private GitHub repository `resumeops`, initializing/committing the independently reviewed sanitized source, pushing that source and running credential-free Ubuntu CI. This authorization is limited to private source verification. It does not authorize a public repository, public personal-content publication, AWS resources/API execution, cloud roles or credentials, IAM changes, Terraform plan/apply/destroy, live deployment, merge or destruction. Before push, independently audit the exact intended source and ensure the remote is private. No credentials, private contacts, PDFs, plans, state, local diagnostic payloads or tool/cache directories may be committed.

For implementation acceptance, successful independently verified Ubuntu CI on the exact reviewed source revision is an approved alternative to native Windows Terraform provider startup. CI must run the pinned Terraform/provider versions and committed lockfiles, recursive format checking, and `init -backend=false -input=false -lockfile=readonly` followed by `validate` for both bootstrap and site roots, without AWS credentials/backend access or weakened TLS/mTLS. The full required verification suite and individual scanner-exception assessment remain mandatory. Record immutable commit/run links and actual exit results; a queued, cancelled, incomplete or failed run cannot pass. Native Windows provider startup/validation limitations remain separately reported and are never relabeled as successful. This alternative does not waive deployed verification or alter source security, lockfile, cost or budget requirements.

During private verification, only credential-free validation workflows may be executable under `.github/workflows`. Preserve future AWS/deploy/drift/rollback/destructive workflow implementations as inert source templates outside that directory, without active dispatch, schedule or other GitHub workflow triggers. Active workflows must have no `id-token: write`, AWS authentication, role-assumption, remote-backend, Terraform plan/apply/destroy or deployment path, including indirectly invoked scripts. A variable defaulting to disabled is insufficient isolation. Restoring operational workflows requires separate explicit human authorization and independent review of the enabling change.

Report five distinct verdicts: native Windows validation readiness; credential-free CI implementation readiness; private GitHub verification readiness; public publication readiness; and live AWS release readiness. CI success may establish implementation readiness despite the separately recorded Windows limitation. Private verification requires an actually private intended repository, independently reviewed sanitized source and successful credential-free CI at the reviewed revision. Public publication still needs explicit human approval. Live AWS release still needs separate explicit authorization and all original mandatory live evidence. Neither private verification nor any readiness verdict grants broader authority. Preserve the low-traffic target below USD 1/month, USD 5 monthly budget and private actual-spend alerts at USD 1/3/5 unchanged.
